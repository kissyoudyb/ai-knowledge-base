# 技术深度分析技能

## 使用场景

- 对 `knowledge/raw/` 中采集的原始数据进行深度分析
- 提炼技术亮点评分排序，发现跨项目趋势
- 为分发环节提供高质量、结构化的分析结果

## 执行步骤

1. **读取数据** — 从 `knowledge/raw/` 中读取最新采集的 JSON 文件（按文件名日期排序取最新），解析 `items` 数组作为分析对象。
2. **逐条深度分析** — 对每个项目执行四维分析：
   - **摘要** — 用不超过 50 字提炼核心价值，不含主观评价。
   - **技术亮点** — 列出 2–3 个具体亮点，用事实和数据说话（如支持的模型数、性能提升百分比、 GitHub Star 增速等）。
   - **评分** — 按下方评分标准给出 1–10 的整数分数，并附简要理由。
   - **标签建议** — 推荐 2–4 个标签（如 `multi-agent`、`rag`、`fine-tuning`），优先复用已有标签库。
3. **趋势发现** — 综合分析全部项目，提取 2–4 个共同主题（如「本周 Agent 框架集中爆发」）和 1–2 个值得关注的新概念/新方向。
4. **输出 JSON** — 将完整分析结果写入 `knowledge/articles/github-trending-analysis-YYYY-MM-DD.json`。

## 评分标准

| 分数  | 含义       | 说明                       |
| ----- | ---------- | -------------------------- |
| 9–10  | 改变格局   | 可能重塑技术栈或行业范式   |
| 7–8   | 直接有帮助 | 能解决具体问题，可立即采用 |
| 5–6   | 值得了解   | 有参考价值，但非必需       |
| 1–4   | 可略过     | 创新不足或与领域关联度低   |

## 注意事项

- 📏 每条摘要严格不超过 50 字，超出需截断或重写。
- 🔢 9–10 分的项目在 15 个中不得超过 2 个，确保评分有区分度。
- 🎯 技术亮点必须基于事实（引用数据、功能、性能等），禁止泛泛而谈。
- 🏷️ 标签建议保持一致性，优先使用已有标签（参考 `knowledge/articles/` 中历史记录）。
- 📊 评分需附理由，不能只给数字。理由应指向具体的技术特征或数据。
- 📁 不足 15 条时按实际数量输出，不强制补足。
